Run date: 2026-08-18
Branch: `agent/mxfp4-progressive-q2-q3-q4`

## 1. Executive conclusion

The exact embedded hierarchy is a materially better progressive representation than the scalar RRQ baseline. It reconstructs the authoritative MXFP4 expert weights exactly after two streamed refinement bits, removes the prior 2.6–2.7× page amplification, and transfers well from the cross-reference pilot to fresh activations captured from the exact MXFP4 checkpoint.

On the primary difficult-layer aggregate (layers 4/20/39), the deployment-oriented one-layout, 512-byte selective oracle achieved:

| Physical correction bpw | p10 recovery | Median | p90 | Fraction ≥90% | Reference-stream reduction |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 0.50 | 54.33% | 69.99% | 80.84% | 0.00% | 8.50× |
| 0.75 | 68.88% | 81.09% | 88.35% | 7.77% | 5.67× |
| 1.00 | 80.45% | 88.18% | 93.19% | 36.89% | 4.25× |
| 1.25 | 87.71% | 93.14% | 96.46% | 79.61% | 3.40× |
| 1.50 | 94.31% | 96.67% | 98.46% | 100.00% | 2.83× |
| 2.00 | 100.00% | 100.00% | 100.00% | 100.00% | 2.13× |

Those exploratory results used the pre-existing aligned Qwen3.6 BF16 activations with exact MXFP4 weights. A locked-hierarchy confirmation on 12 fresh requests executed through the exact checkpoint produced difficult-layer p10/median/p90 of **83.34/89.35/95.35% at 1.0 bpw**, **90.41/94.29/97.27% at 1.25 bpw**, and **95.27/96.98/98.85% at 1.5 bpw**. The main rate–distortion trend therefore transferred.

The strong one-bpw criterion is narrowly missed: the fresh difficult-layer median is 89.35%, not 90%. The 1.5-bpw criterion passes comfortably and implies 2.83× less external traffic than streaming the 4.25-bpw exact reference. This supports continued development, but it is not yet a model-quality claim because causal injection/replay has not passed an identity test.

The main remaining opportunity is allocation, not codec fidelity. On a bounded exact-marginal audit, 90% gate/up projection recovery required 2.4–3.2× fewer refinement actions than diagonal ranking. A paired-Q3+Q4-plane action control also improved the matched-subset median at 1 bpw from 92.25% to 94.10% in the fresh capture. These should be combined before H4 training.

## 2. Authoritative model and checkpoint facts

The study did not reinterpret Q5_K/Q6_K GGUF tensors as MXFP4 and did not dequantize/requantize a BF16 model to manufacture a reference.

The authoritative checkpoint was [pahajokiconsulting/Qwen3.6-35B-A3B-MXFP4](https://huggingface.co/pahajokiconsulting/Qwen3.6-35B-A3B-MXFP4), revision:

```text
7eceff3a9f7e6f916c824d197266d86676bce695
```

Its base model is `Qwen/Qwen3.6-35B-A3B`. Discovered architecture:

| Fact | Discovered value |
| --- | ---: |
| Routed layers | 40 |
| Routed experts/layer | 256 |
| Experts selected/token | 8 |
| Hidden dimension | 2,048 |
| Expert intermediate dimension | 512 |
| Gate/up geometry | 512 × 2,048 |
| Down geometry | 2,048 × 512 |
| Weights/projection | 1,048,576 |
| Weights/expert | 3,145,728 |

The checkpoint declares compressed-tensors `mxfp4-pack-quantized`, group size 32, E2M1 leaf values and E8M0 scale codes. Every routed expert gate/up/down pair in layers 0/4/20/39 was audited: 3,072 expert/projection pairs and 6,144 packed-code/scale entries. Every tensor was `uint8`, had the expected geometry, and repacked exactly after nibble unpacking. The aggregate exact-stream SHA-256 is:

```text
28ea957daf4248338116620c0be810b70852f85cfcbb098d2f6712940a54e45e
```

The exact reference costs 4.25 bpw: 4 bits for leaf codes plus one E8M0 scale byte per 32 weights (0.25 bpw). One projection is 557,056 bytes and one complete expert is 1,671,168 bytes.

## 3. Data and separation

### Cross-reference exploratory oracle

The main broad pilot reused the existing Qwen3.6 BF16 capture because it has the required alignment and H1–H4 router fields. It contains 5,036 rows across 81 complete requests: 53 training, 12 validation and 16 test requests. Splitting is by complete request. The primary dense study sampled two hot, two median and two cold experts per layer (24 experts, 285 held-out invocations). The selective study sampled one per stratum (12 experts, 142 held-out invocations).

This is explicitly cross-reference exploratory evidence: the weights are the exact MXFP4 checkpoint weights, but the activations were not generated by that checkpoint.

### Fresh exact-checkpoint confirmation

The checkpoint was loaded through Transformers 5.15 and compressed-tensors 0.18 with `dequantize=True`, which decodes the original packed E2M1/E8M0 checkpoint representation without requantization. Twelve new text requests were executed, with 6/3/3 complete-request train/validation/test separation. Hooks captured pre-MoE inputs, post-layer states, router logits, top-8 IDs/weights and aligned H1–H4 states at layers 0/4/20/39. This produced 564 rows: 280/128/156 by split. The raw NPZ hash is:

```text
84b7e727d774f6393d7e4e4cb5304c7df283b817002b48813a30ff55e6262e61
```

The hierarchy was locked before this confirmation. The dense confirmation contains 85 test invocations; the selective confirmation uses the same 85 invocations and three test-request clusters. Its confidence intervals are therefore useful as a small confirmation, not a substitute for a larger request sample.

## 4. Exact embedded hierarchy

For each exact MXFP4 leaf code `c`, a balanced bijection stores:

```text
c ↔ (two-bit parent p, first refinement bit r1, second refinement bit r2)
```

The reconstructions are `C2[p]`, `C3[p,r1]`, and the exact MXFP4 E2M1 leaf at level four. The original E8M0 block scale is shared by all levels. Thus:

* resident parent: 2-bit indices + 0.25-bpw scales = 2.25 effective bpw;
* first external plane: 1 bpw, yielding embedded Q3;
* second external plane: 1 bpw, yielding the exact 4.25-bpw checkpoint representation;
* final equality is code-exact, not approximate.

Candidate balanced trees were natural, sign-preserving learned and unrestricted learned. Parent/child reconstructions were either free FP16 centroids or E2M1-constrained values. Training built the candidates; validation selected one layer-independent configuration per projection using a lexicographic Q2-then-Q3 objective. The selected trees were:

| Projection | Tree | Parent/Q3 centroids |
| --- | --- | --- |
| Gate | Natural | E2M1 constrained |
| Up | Natural | Free FP16 |
| Down | Natural | Free FP16 |

The learned tree permutations did not improve the validation result. The free-centroid up/down hierarchy is a small-LUT accuracy configuration, not a claim that Q3 is a native Tensor Core datatype. The exact Q4 endpoint remains native E2M1 plus E8M0 scales.

The embedded parent was close to the preceding activation-aware Q2 comparator but heterogeneous. On the exploratory all-layer set, old-Q2 damage divided by embedded-parent damage had p10/median/p90 0.613/1.070/1.790; on difficult layers it was 0.580/0.976/1.673. The fresh confirmation gave 0.615/1.063/1.904 on difficult layers. A parent tree should therefore not be described as uniformly superior.

## 5. Metric and H0 allocation

Recovery is complete sequential-expert proxy-weighted damage recovery relative to the embedded Q2 parent:

```text
recovery = 1 - D(candidate) / D(embedded Q2)
```

Gate and up are passed through the actual sequential SwiGLU, and the candidate down matrix is applied to the resulting approximate intermediate. The proxy adds a low-rank H1–H4 future-router-boundary sensitivity term fitted on training requests. Test activations are used only for H0 support choice, as intended by an oracle study.

Each selectable action upgrades one input direction by one bit. Actions are nested: Q3→Q4 is eligible only after Q2→Q3. Gate/up actions carry 512 output bits (64 bytes); down actions carry 2,048 bits (256 bytes). Static diagonal action scores initialize a nested path for each projection. The final allocator exhaustively evaluates the 9×9×9 combinations of gate/up/down support rates under one complete-expert physical-byte budget and chooses the lowest exact sequential-expert damage. It is exact over those three constructed support paths, not an unrestricted complete-expert beam over all actions.

## 6. Phase A: dense hierarchy

Dense Q3 is not strong enough by itself. On the exploratory difficult-layer set, `(Q3,Q3,Q3)` had p10/median/p90 recovery of 43.78/63.01/77.09%. On the fresh exact capture it had 37.30/59.05/72.03%.

Asymmetry matters. Fresh difficult-layer results include:

## 8. Selective-versus-dense retention

The requested retention is:

```text
eta(B) = [D(Q2) - D(selective at B)] / [D(Q2) - D(best dense tuple at or below B)]
```

Values above one mean selective bits outperform the best dense prefix at the same byte budget. Fresh difficult-layer p10/median/p90:

| Physical bpw | p10 eta | Median eta | p90 eta |
| ---: | ---: | ---: | ---: |
| 0.50 | 1.502 | 2.126 | 3.560 |
| 1.00 | 1.119 | 1.278 | 1.587 |
| 1.50 | 1.080 | 1.169 | 1.360 |
| 2.00 | 1.000 | 1.000 | 1.000 |
| 2.50 | 1.000 | 1.000 | 1.000 |
| 3.00 | 1.000 | 1.000 | 1.000 |

The 2.5/3.0 values are exact saturation, not extrapolation: the full suffix is already present at 2 bpw. The result directly confirms that activation-dependent selectivity is useful rather than merely riding on a better dense codec.

## 9. Interaction and ranking regret

The primary diagonal score ignores cancellation and cross terms. One held-out invocation per audited layer was reranked with exact projection-residual OMP and backward elimination. Actions required for 90% projection recovery in the fresh confirmation were:

| Layer | Projection | Diagonal | Exact OMP | Backward elimination |
| ---: | --- | ---: | ---: | ---: |
| 0 | Gate | 774 | 242 | 266 |
| 0 | Up | 620 | 221 | 241 |
| 0 | Down | 134 | 126 | 125 |
| 4 | Gate | 1,649 | 690 | 695 |
| 4 | Up | 1,619 | 482 | 561 |
| 4 | Down | 311 | 280 | 281 |
| 20 | Gate | 1,699 | 548 | 617 |
| 20 | Up | 1,679 | 510 | 582 |
| 20 | Down | 286 | 264 | 262 |
| 39 | Gate | 980 | 377 | 404 |
| 39 | Up | 1,531 | 450 | 514 |
| 39 | Down | 168 | 153 | 152 |

This is a bounded diagnostic, not an aggregate oracle. It nevertheless shows that diagonal ranking makes gate/up support appear 2.4–3.2× broader at the 90% crossing. Down gains are smaller. The next allocator should use incremental Gram/correlation updates for linear candidate paths and exact sequential-expert rescoring for finalists.

The stage-specific supplement repeats 80/90/95/99% crossings separately for the two one-bit planes. In the fresh confirmation at 90%, exact greedy versus diagonal required a median **2.42× fewer gate/up coordinates**, but only 1.05× fewer down coordinates. Both planes show the same qualitative result; the second plane does not become broadly harder. Up to eight local swaps added a median 0.127 recovery points at fixed greedy support (maximum 0.298), so most bounded ranking gain came from residual-aware greedy rather than swaps. Beams of width 16/64/256 over the top-32 energy candidates converged to the same best depth-12 curve; wider beams gave no measurable gain in this deliberately small search. Full 80/90/95/99 rows and beam curves are saved in `stage_specific_support_summary.csv` and `bounded_beam_summary.csv`.

The prior RRQ request for three stage-specific support curves does not map one-to-one to this format: the exact hierarchy has two one-bit refinement planes, not three RRQ residual stages.

## 10. Complete-expert bandwidth allocation

On exploratory difficult-layer invocations, the fraction of physical payload allocated to gate/up/down at 1.0 bpw was 36.4/36.9/26.7%; at 1.5 bpw it was 36.8/37.5/25.7%. The fresh confirmation gave 39.8/34.7/25.5% and 39.7/36.0/24.3%, respectively.

Median per-projection support-rate targets in the fresh confirmation were `(1.25, 1.0, 0.75)` at a 1.0-bpw total average and `(1.75, 1.5, 1.0)` at 1.5 bpw. The units are per-projection correction bpw; their average is bounded by the complete-expert budget. Unlike PR #3 RRQ, down is no longer the dominant byte consumer. Gate Q3 weakness and gate/up ranking interactions now dominate.

## 11. Phase C: page and layout results

The scale stream is shared and resident. Refinement streams contain only bitplanes: no per-atom header, scale or zero point. Identity is implicit in the fixed offset. One 512-byte page holds eight gate or up directions in one plane, or two down directions. The primary training-only co-selection layout achieved physical/logical amplification of **1.000×** at every reported budget.

On the 12-invocation exploratory layout subset at 1.0 bpw, median recovery was 88.65% for naive order, 89.50% for one co-selection layout, 90.32% for average-importance order, 90.83% for H0-best of two replicas and 90.87% for H0-best of four replicas. Fresh-confirmation matched-subset medians were 88.30%, 92.25%, 92.49%, 92.30% and 93.05%. Replica choice is an H0 upper bound, not a deployment policy.

At one bpw the one-layout exploratory medians were 89.50/85.54/82.66% for 512-byte/1-KiB/4-KiB pages. Fresh confirmation gave 92.25/89.60/89.19%. The best page size is 512 bytes.

A paired-plane control makes both refinement bits for a coordinate one action. On the small matched subset it improved the one-bpw median from 89.50% to 93.67% exploratory and from 92.25% to 94.10% fresh-confirmation. At 1.5 bpw the fresh medians were 97.69% separate versus 99.12% paired. This is promising but changes the action granularity and must be validated on the full set before replacing the primary representation.

Naively bundling gate/up selected supports into shared natural-coordinate pages was harmful: median physical bytes were 1.58× the independent layout at a one-bpw operating point because unwanted payload outweighed page reuse. Jointly optimizing bundled supports was not performed.

## 13. Compute accounting

One full exact expert GEMV is 6,291,456 multiply-add FLOPs under the study's two-FLOP convention. A selected one-bit coordinate refinement accumulates one output vector. The analytical additional FLOPs are therefore approximately `B` times one full expert GEMV at `B` correction bpw:

| Correction bpw | Extra FLOPs | Extra/reference GEMV | Total base+correction arithmetic | External bytes/expert |
| ---: | ---: | ---: | ---: | ---: |
| 0.50 | 3.146M | 0.50× | 9.437M | 196,608 |
| 1.00 | 6.291M | 1.00× | 12.583M | 393,216 |
| 1.25 | 7.864M | 1.25× | 14.156M | 491,520 |
| 1.50 | 9.437M | 1.50× | 15.729M | 589,824 |
| 2.00 | 12.583M | 2.00× | 18.874M | 786,432 |

Correction arithmetic intensity is about 16 FLOP per external byte. Including resident parent reads, the analytical intensity is 9.85 FLOP/byte at one bpw and 10.67 at 1.5 bpw. With the preceding study's 273 GB/s GB10 memory-bandwidth assumption, these remain memory-bound points; the analysis does not claim measured Spark latency. Lookup/unpack, scheduling and output-write costs are omitted and need a fused-kernel microbenchmark. RTX PRO 6000 timings were construction/evaluation timings, not Spark serving measurements.

The following invariants were tested:

* exact E2M1 nibble unpack/repack;
* exact 2-bit parent and 1-bit plane pack/unpack;
* balanced 16-leaf bijection and exact Q4 reconstruction;
* E8M0 block-scale decode and geometry;
* nested action eligibility;
* exact action/page/decoded-contribution identity;
* incremental page costs and duplicate-page reuse;

## 15. Limitations

1. The larger 142-invocation result is cross-reference exploratory. The exact-checkpoint confirmation has only 85 invocations and three test requests.
2. Direct mixed-output injection and H1–H4 replay identity were not implemented. Captured H1–H4 states support the proxy, but no router-recall, KL or token-agreement claim is made.
3. The primary action order is diagonal and static. Exact OMP/backward elimination was bounded to one invocation per audited layer.
4. Local swaps and width-16/64/256 beams are also bounded per-plane diagnostics; complete-expert allocation is exact only over three preconstructed projection paths, not a global action beam.
5. Top-8 experts are evaluated as routed expert invocations, not under one aligned combined MoE budget.
6. Free FP16 up/down centroids need LUT expansion and are an accuracy-oriented hierarchy, not a native Q3 datatype.
7. The 1.000× amplification result assumes stage-aligned packed bitplanes and fully usable returned pages. Kernel-side unpack and cache behavior remain unmeasured.
8. The early Qwen3.5 checkpoint run was invalidated immediately after the model-version mismatch was discovered. Its small method-development artifacts are retained only for audit transparency and are excluded from every conclusion.

## 16. Decision

The exact embedded hierarchy passes the codec endpoint and 1.5-bpw selective criteria:

* exact Q4 reconstruction: pass;
* page amplification ≤1.4×: pass at 1.0×;
* 1.0 bpw median ≥90%: narrow miss at 89.35% fresh-confirmation;
* 1.0 bpw p10 approximately 80–85%: pass at 83.34%;
* 1.5 bpw median ≥95% and p10 ≥90%: pass at 96.98% and 95.27%;
* external storage ≤5×: pass at 1.471× primary;
* exact-checkpoint transfer: pass for the small capture;
* replay quality: unavailable.

This justifies a broader confirmation after one more allocator iteration. It does not justify H4 training yet because a better interaction-aware action policy would change the labels substantially.

## 17. Recommended next experiment

1. Replace diagonal paths with scalable incremental-correlation OMP, then rescore the top candidate actions with exact sequential SwiGLU damage. Add backward local elimination and swaps.
2. Promote paired exact-refinement packets to a full validation-selected comparison; the small control gained 1.8–4.2 median points at one bpw.
3. Jointly optimize page contents and support, rather than bundling a support chosen for independent layouts.
4. Expand the exact-checkpoint capture to at least 16 held-out requests and retain the locked hierarchy. Do not select from the current three-request confirmation.
5. Build an injection hook in the same compressed-tensors execution path, pass unchanged-output identity, and only then report H1–H4 router/logit/token metrics.
6. Run an aligned top-8 page allocator after the per-expert interaction-aware path is stable.
7. If one-bpw median still remains below 90% after interaction-aware allocation, try a four-weight product-vector 2+1+1 hierarchy before revisiting global residual bases.
