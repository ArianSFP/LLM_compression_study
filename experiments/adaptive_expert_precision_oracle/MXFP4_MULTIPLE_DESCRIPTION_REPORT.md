## 1. Executive conclusion

Allowing either exact MXFP4 suffix bit to arrive first is mathematically correct, requires no additional stored weight bits, and preserves the exact two-bit endpoint. It is **not a material codec improvement for the hierarchy already selected in PR #4**.

The reason is structural rather than statistical. The existing tree was selected lexicographically for the resident Q2 parent and then for the `A` Q3 partition. Consequently, full-support `A` recovers far more projection error than `B` or parity `Q=A xor B`. Across all saved budget/action traces, the controlled bidirectional allocator chose a `B`-first action only 172 times versus 1,370,156 `A`-first actions. With direct two-bit actions disabled, it chose `B` first 1,249 times versus 1,394,956 `A` actions—about 0.09% of first-bit actions. A controlled parity run chose `Q` **zero times**.

At 1.0 physical correction bpw on difficult layers 4/20/39, the primary bidirectional policy achieved p10/median/p90 complete-expert proxy recovery of **85.34/91.81/99.04%** over 54 held-out expert invocations from six fresh test requests. The paired median gain over ordered `A`-first was only **+0.019 recovery points**. A dedicated ablation shows that this gain came from allowing a direct two-bit `AB` action, not from `B` being eligible first:

| Change at 1.0 physical bpw, layers 4/20/39 | p10 paired change | Median | p90 | Mean | Fraction improved |
| --- | ---: | ---: | ---: | ---: | ---: |
| `B` first only, direct `AB` disabled | -0.025 pt | 0.000 pt | +0.136 pt | +0.025 pt | 11.1% |
| Direct `AB`, first bit fixed to `A` | -0.392 pt | **+0.019 pt** | +0.468 pt | **+0.122 pt** | 51.9% |
| Add `B`-first after direct `AB` exists | 0.000 pt | **0.000 pt** | 0.000 pt | -0.003 pt | 0.0% |
| Add parity `Q` on the identical A/B layout | 0.000 pt | **0.000 pt** | 0.000 pt | 0.000 pt | 0.0% |

The parity proposal therefore fails its practical test for the locked tree: it raises the one-layout fallback-plus-suffix storage multiplier from **1.471× to 1.706×**, yet produces bit-for-bit identical recovery and bytes to bidirectional A/B in all 490 controlled invocation-budget pairs.

Recommendation: retain direct `AB` as a legal H0 action, keep `B`-first only as a cheap optional scheduler state, and do **not** store parity for this tree. If multiple descriptions are revisited, refit the parent tree with an explicit best-of-`A/B/Q` one-description objective. The higher-priority next work remains interaction-aware forward/backward selection and validated model replay.

## 3. Codec under test

For each exact MXFP4 leaf code `c`, the locked hierarchy defines a bijection:

```text
c <-> (two-bit resident parent p, exact suffix bits a and b)
```

The existing system decodes `C2[p]`, then `C3A[p,a]`, then the exact E2M1 leaf `C4[p,a,b]`. This study adds:

* `C3B[p,b]`, fitted from training-only functional leaf masses;
* optional `q=a xor b` and `C3Q[p,q]`;
* exact reconstruction from any two distinct descriptions;
* direct two-plane actions from Q2 to exact Q4;
* explicit page and state identities for every selected action.

The original `C3A` table is not refitted. This preserves the deployed PR #4 hierarchy and makes the comparison an action/description ablation rather than a new tree search. Gate uses E2M1-constrained centroids; up and down use serialized FP16 free centroids, matching the locked configuration.

At runtime, every one-bit description for a natural input coordinate contributes one output vector. Gate/up packets are 64 bytes per description; down packets are 256 bytes. Bitplanes contain no per-coordinate scale or header because the exact checkpoint scale table is shared and resident and coordinate identity is implicit in the fixed layout.

## 4. Oracle and metric

Recovery is measured against the locked embedded-Q2 complete expert:

```text
recovery = 1 - D(candidate) / D(embedded Q2)
```

`D` is the exact sequential SwiGLU output error plus the prior study's rank-4 future-router-boundary proxy. Gate and up corrections are passed through SiLU and multiplication; down is applied to the resulting approximate intermediate. For each projection, actions are scored by exact within-coordinate residual reduction in an augmented proxy space. The complete-expert allocator then exhaustively checks the Cartesian product of the constructed gate/up/down rate paths and chooses the lowest exact sequential-expert damage under the physical byte budget.

This is an H0 activation-dependent oracle, but it remains a scalable diagonal coordinate ranking. It is not an unrestricted exact greedy or beam search over the nonlinear complete-expert action set. Negative paired results after expanding the action set are therefore allocator regret, not evidence that the extra legal representation can mathematically reduce the optimum.

Training requests fit `B/Q` centroids and co-selection page layouts. Validation outcomes inherited the locked base hierarchy. Held-out activations select H0 actions but do not fit centroids or layouts. Final intervals use 1,000 request-cluster bootstrap resamples.

The parity shared-layout run is identical to bidirectional A/B in recovery, logical bytes, physical bytes and selected state for all 490 paired rows. The apparent differences seen when parity was allowed to train its own layout were entirely layout perturbation: at one bpw the difficult-layer paired parity-minus-bidirectional median was -0.055 points with a -2.20/+2.29-point p10/p90 spread and a bootstrap interval spanning zero.

### 6.3 Isolating B-first from direct AB

The original `bidirectional_ab` policy changed two things: it allowed B first and it introduced a direct exact AB action. The dedicated ablation isolates them.

At one bpw on difficult layers, B-first without direct AB had zero paired median benefit. A non-deployable per-invocation best-of ordered and bidirectional-no-direct policies shows a mean upside of only 0.047 recovery points, p90 0.136 points and maximum 0.733 points; only 11.1% of invocations improve. Direct AB with A fixed first yielded +0.122 mean and +0.019 median points. Once direct AB exists, adding B first improved no invocation in this budget slice.

At low rates the greedy expanded policy can be worse on some invocations. Since ordered A remains a legal subset, an exact optimizer would take the better path. This regret reinforces the prior conclusion that selection interactions—not another suffix description—are now the dominant opportunity.

## 7. Page size and storage

The primary 512-byte result has virtually no read amplification. A 512-byte page contains eight one-bit gate or up directions or two one-bit down directions. The bounded 1-KiB/4-KiB diagnostics cover only one held-out expert invocation per layer, so they are directional only. Recovery changes with page size chiefly because larger pages force different co-selection groups, not because dense padding becomes large. At one bpw, the four-invocation bidirectional medians were 92.74% at 1 KiB and 87.62% at 4 KiB.

Storage including the exact 4.25-bpw fallback:

| Suffix | Layout copies | Stored suffix bpw | External/reference multiplier |
| --- | ---: | ---: | ---: |
| A/B | 1 | 2 | **1.471×** |
| A/B | 2 | 4 | 1.941× |
| A/B | 4 | 8 | 2.882× |
| A/B/Q parity | 1 | 3 | **1.706×** |
| A/B/Q parity | 2 | 6 | 2.412× |
| A/B/Q parity | 4 | 12 | 3.824× |

All fit under the 5× cap. Capacity is not the issue: parity's additional stored bitplane provides no selected actions or quality.

## 8. Correctness and statistical checks

The implementation tests:

* balanced A/B/Q partitions within every parent;
* exact leaf reconstruction from AB, AQ and BQ;
* exact Q4 output after any two descriptions;
* exact description-plane page identity;
* direct-pair physical cost and duplicate-page reuse;
* exact correspondence among charged pages, actions, state masks and decoded output;
* deterministic co-selection layout and allocator behavior;
* request-level train/validation/test separation.

Every selected action row retains request/sequence/token/layer/expert/projection, exact coordinate IDs, before/after masks, description names, marginal utilities, per-action page IDs, final page union, logical bytes and physical bytes. The main 132-MiB action monolith was split losslessly by layer into four Zstd Parquet files so every GitHub object remains below 100 MiB.

The complete oracle-study suite passes 49 tests. Figures and confidence intervals are reproducible from the committed metric files with the commands in the ledger.

## 9. Limitations

1. Recovery is a sequential complete-expert future-router proxy, not validated H1–H4 causal replay. No router-recall, logit-KL or token-agreement claim is made.
2. There are only six held-out request clusters and 70 capped expert invocations. Confidence intervals are cluster-correct but this remains a bounded pilot.
3. The tree was intentionally locked from PR #4. This answers whether extra descriptions help that deployed hierarchy, not whether a newly co-designed multiple-description tree could help.
4. The allocator uses static within-coordinate marginals followed by exact allocation across constructed projection rate paths. It is not exact complete-expert greedy, OMP, backward elimination or beam search.
5. The page-size diagnostic is only four invocations. The 512-byte primary result is broad; 1-KiB/4-KiB comparisons are not.
6. No aligned joint top-8 allocation and no H4 predictor were run.
7. Timings are measured on an RTX PRO 6000 and are not DGX Spark serving timings.

## 10. Decision and next experiments

### Bidirectional first bit

**Technically valid, practically neutral.** It costs no additional external suffix storage, so retaining the state transition is harmless if scheduler complexity is negligible. It should not be presented as a material quality improvement. Direct AB is the useful addition and should remain.

### Parity multiple description

**No-go for the locked hierarchy.** Q was selected zero times and the controlled frontier is identical. Do not spend an extra stored bpw or layout replicas on it.

### Recommended order

1. Replace static diagonal scoring with incremental residual-aware OMP/forward marginal updates and backward elimination from the exact endpoint. Use exact sequential-expert rescoring for projection-path finalists.
2. Retain direct AB/paired-plane pages. Jointly optimize whether a coordinate should receive one useful bit or both exact bits; this is more valuable than choosing B first.
3. Validate the best allocator in the exact checkpoint execution path with an identity-tested MoE-output injection hook, then run teacher-forced H1–H4 replay.
4. Allocate pages jointly across the aligned top-8 experts using router coefficients and page unions.
5. Only if multiple-description coding remains attractive, refit a new tree with a training/validation objective such as `min D(Q2)` subject to maximizing the best of A/B/Q at one bit and exactness at two bits. Compare its Q2 loss and best-single-description gain before building pages. A parity plane should not be added to a tree optimized solely for A.
6. If interaction-aware allocation still misses the desired frontier, move to four-weight product-vector hierarchy or complete-expert residual VQ/local-affine atlases.
